日記型の画面遷移

骨格 4 案の C を実装に落とす。 画面は 3 つ。スイングの一覧（ホーム）、動画を選ぶ画面（「動画」「お手本」の 2 タブ）、ステージ（比較）。 選ぶ画面の中にプレビューと名前付けが入り、フェーズ調整は既存のまま。

第 2 稿での変更：写真ピッカーは 1 本だけ選ぶ（複数選択と「一覧に戻る」の線を削除）。ピッカーを自作し、上に「動画」「お手本」のタブを置く。 ステージの左の＋は「動画」タブ、右の＋は「お手本」タブが開いた状態で始まる。これでお手本の棚は独立した画面でなくなり、ホームのお手本チップも不要になった。 自作ピッカーは写真ライブラリの権限を取るので、スロー動画の原本取得（TODO A）を同じ作業で片付ける。
§0 全体図

画面と遷移

太枠が 3 画面。ホームとステージは NavigationStack のプッシュ、動画を選ぶ画面は全画面のシート。タブは 2 つの間で自由に切り替えられ、どちらから選んでも「押した側のペインに入る」規則は同じ。

§6 データと保存

クリップ 1 種類に寄せる

スイングもお手本も「動画 1 本 ＋ 解析結果 ＋ 名前 ＋ ★」なので、型は 1 つにして役割で分ける。ペアの記憶（相手と右ペインの位置合わせ）はスイング側が持つ。「いつものお手本」は保存せず、最後に比べた相手から導く。

enum ClipRole: String, Codable { case swing, model }

/// 取り込んだ動画 1 本。スイング（左ペイン）もお手本（右ペイン）も同じ型
struct Clip: Codable, Identifiable, Equatable {
    var id: UUID
    var role: ClipRole
    var name: String              // 空なら日時を表示
    var createdAt: Date           // 取り込み日時
    var shotAt: Date?             // 撮影日時（PHAsset.creationDate）。一覧の並びと節はこちら
    var isFavorite: Bool          // スイング: ★ ベスト（「お手本」タブにも並ぶ）。お手本では使わない
    var video: VideoConfig        // 現行のまま（fileName / phases / candidates / focusRect / 自分側の scale・offset）
    var analysis: AnalysisState   // queued / analyzing / done / failed(message)。done 以外は開けない
    var pairing: Pairing?         // 最後に比べた相手と、そのときの右ペインの位置合わせ
}

struct Pairing: Codable, Equatable {
    var partnerID: UUID           // お手本（role == .model）か ★ のスイング
    var scale: Double = 1, offsetX: Double = 0, offsetY: Double = 0
}

/// Documents/library.json
struct Library: Codable {
    var clips: [Clip]
    var reference: ReferenceSide  // 同期の基準（アプリ全体で 1 つ）
}
規則内容
ホームに出るものrole == .swing。★ は「★ ベスト」の節、それ以外は shotAt ?? createdAt の日ごと。新しい順
「お手本」タブに出るもの「登録済み」= role == .model、「★ ベスト」= role == .swing && isFavorite
いつものお手本保存しない。role == .swing を新しい順に見て最初の pairing.partnerID（現行の lastUsedModelID と同じ考え）
相手の解決pairing.partnerID のクリップ → 無ければいつものお手本 → 無ければ ⊕。解決した相手が pairing と違えば pairing を更新（位置合わせは初期値）
流す上限追加のたびに、role == .swing && !isFavorite && analysis == .done を新しい順に 60 本残して削除。定数 swingLimit
削除と元に戻すJSON から外すだけ。動画ファイルは次回起動時に参照の無いものを消す（現行）。「元に戻す」は外したクリップをメモリに持って戻す
お手本の削除確認あり。相手にしていたスイングの pairing は残し、開くときに上の解決規則で置き換わる
解析キューanalysis != .done のクリップを createdAt 順に 1 本ずつ。起動時にも走らせる
取り込みPhotoKit（PHImageManager.requestAVAsset、version = .original）で原本を Documents/Videos/ へ書き出し → 音声除去 → 解析。許可なしのときは現行の PhotosPicker 経路。同じ動画はサイズと長さで照合し、ファイルと解析結果を共有

旧データ（projects.json・models.json）

  1. models.json の各 ModelVideo → Clip(role: .model)（id・name・createdAt・config をそのまま）
  2. projects.json の各比較 → 左を Clip(role: .swing, pairing: 右)。右は modelID があればそのお手本を相手に、無ければ Clip(role: .model, name: "お手本 M/d HH:mm") を作って相手にする（同じ fileName のお手本が既にあればそれ）
  3. 右ペインの位置合わせ（model.scale / offset）は pairing へ。基準は最新の比較の値
  4. 書けたら旧ファイルを消す

STEP 3
動画を選ぶ
VideoPickerSheet を 2 タブに作り替え。「動画」タブ: PhotoKit の権限（許可 / 限定 / 拒否）、動画だけのグリッド（PHFetchResult + PHCachingImageManager）、プレビュー、原本の書き出し。「お手本」タブ: 現行のカード ＋ ★ ベスト。名前付けは現行のまま。HistoryView は削除
STEP 4
ステージ
StageView を「スイング 1 本 ＋ 相手」の入力に。ツールバー（‹ / ☆ / …）、左右のラベルからタブ指定で選ぶ画面へ、解析中・お手本なし。ComparisonView の保存先を pairing に
STEP 5
E2E と文書
FlowTests を新フロー（＋ → 動画タブ → プレビュー → ステージ → ‹ → 行 → 右ラベル → お手本タブ）に書き直し。SPEC §2.1 §2.5 §5、ARCHITECTURE §2、README、ROADMAP、TODO A を閉じる、build-test

変わらないもの: PlaybackController、SyncEngine、解析（SwingAnalyzer 以下）、PhaseEditView、VideoPaneView の変換、VideoThumbnail。E2E はシミュレータの写真ライブラリに対して PhotoKit の権限ダイアログが出るので、ハーネスで許可を押す手順が増える。

§8 決めたこと

実装前に覆せる判断

一
動画は 1 本ずつ選ぶ
複数選択と「一覧に戻る」経路は持たない。選んだらプレビュー → ステージ
二
ピッカーは自作し、「動画」「お手本」の 2 タブ
押した側のペインに入る。左の＋は「動画」タブ、右の＋は「お手本」タブで開く。写真ライブラリの権限を取り、スロー動画の原本を取り込む（TODO A）。拒否時は OS のピッカーへ
三
プレビューは「動画」タブの中
セルをタップで拡大再生 → 使う。「お手本」タブのカードは名前があるのでプレビュー無しで使う
四
ホームにお手本のチップは置かない
「いつものお手本」は最後に比べた相手から導く。替えるのはステージの右ラベルから
五
起動は常にホーム
前回のステージは復元しない
六
左ペインもステージから選び直せる
新しい動画なら新しいスイング（右は引き継ぐ）。フィルムストリップで送る形は後から
七
スイングの削除は即時 ＋ 元に戻す、お手本の削除は確認
影響の広さで分ける。上限による自動削除は通知しない（フッターに明記）
八
同期の基準はアプリ全体で 1 つ。信頼度の低い検出は画面に出さない。スワイプは残すが案内しない
main の決定を保つ
