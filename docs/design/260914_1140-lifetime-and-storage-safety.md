# 保存と非同期処理の寿命の整合性

## 目的

保存・撮影・比較再生の境界を見直し、読み込み失敗や画面の終了、削除が非同期処理に重なっても動画と参照を失わないようにする。
対象はアプリ全体。既存の保存形式（版 2）と Apple 標準フレームワークだけの構成を維持する。

## 変更方針

- `ClipStore` はファイル不在と読み出し失敗を区別する。未知の新しい版、重複 ID、復号できない参照がある場合は保存と自動整理を止める。
  保護状態と退避結果を分け、退避できなくてもホームで保存停止を知らせる。保存の成功が確認できるまでローカル動画を削除しない。
- 撮影ショットの写真ライブラリへの移動は、完了時点のクリップと削除取り消し用の参照を扱う。共有ファイルは参照が残る間削除しない。
- `ShotPipeline` は帯の項目と実行中の仕事の寿命を分ける。帯から項目を消しても実行中の処理は終了まで待ち、入力ファイルを保持する。
- 撮影停止は、進行中のすべての区切り書き込みが完了してから検出の残り・切り出し・全体保存へ進む。
  カメラ準備とリプレイの読み込みも画面を離れた後には再開しない。
  書き込み中の動画は `Documents/CaptureTakes/Pending-<UUID>/` に置く。全体の保存が失敗した回はその作業領域を残し、
  次の撮影の準備や画面の破棄で消さない。完了した回だけ後片付けする。
- フェーズとループ範囲は短い動画や保存した範囲の再利用でも動画・共通時間軸の外へ出さない。
- 非同期で動画を分割するときは、最後に成功したショットが元の ID を引き継ぐ。処理中に変更した名前・お気に入り・相手を反映する。

## 検証

一時ディレクトリを使った保存の回帰テスト、待ち合わせを制御する撮影パイプラインのテスト、短い時間軸の境界テストを追加する。
既存の単体テスト、シミュレータおよび実機向けビルドで検証する。検出の計算に変更が及ぶ場合は解析 CLI と実サンプルでも確認する。
カメラ・PhotoKit・Vision を含む実機固有の動作は、単体テストで確認できた範囲と区別して記録する。
