# フェーズ検出の設計見直し：手の高さで決める

**作成日時**: 2026-09-10 02:36 JST
**前提**: [research/260910_0215](../research/260910_0215-rear-view-phase-detection.md)（後方動画で外れる原因）と、
その §4 で挙げた対策案 P1〜P3 のレビュー。現行ロジックは [ARCHITECTURE.md](../ARCHITECTURE.md) §5
**種別**: 設計（コードは変更していない）

## 1. 結論

- **P1〜P3 は採らない。** 「手首とアドレス位置の距離」という現行モデルを残したまま例外を足す案で、後方視点の本質
  （手首が体に隠れてインパクトの「戻り」が観測できない）に対して根本解にならない。P2 の「実速 0.25〜0.3 秒」という絶対時間の事前値はスロー動画で壊れる
- **代わりに、フェーズを「体に対する手の高さ」で決めるモデルに置き換える。** 高さは視点（正面／後方）にも再生速度にも依存せず、
  4 本のサンプルすべてでアドレス・インパクト（低い）とトップ・フィニッシュ（高い）がはっきり分かれる（§4.1）。
  基準点（アドレス位置）を選ぶ必要が無いので、トップでの静止をアドレスと取り違えることが原理的に起きない
- 手首が隠れて見えない区間（後方視点のトップ〜インパクト）は、**再出現の時刻をインパクト**、**バックスイング : ダウンスイング = 3 : 1 の比**でトップを置く。
  どちらも比率ベースなのでスロー動画でも成り立つ。推定で置いたときは `lowConfidence`
- より本質的な信号として画素の動き量・肩腰の回転・音も検討したが、動き量と回転はサンプルで否定された（§3）。音はインパクトの精密化として後回し
- 変更は `PoseTracker`（腰・首の追加、手首点の連続性）と `SwingDetector`（作り直し）に閉じる。保存形式（`VideoConfig`）は変わらない

## 2. P1〜P3 のレビュー

| 案 | 問題 |
| --- | --- |
| P1 アドレスは手が低い静止点に限る | 方向は正しいが、距離モデルに条件を 1 つ足すだけでは、区間分割（`motionSegments` の `pauseMax`）がトップの静止で切れる問題が残り、切れた後半区間の中で「戻り」を探す構造も残る。結局 P2 が必須になる |
| P2 欠測区間をまたいで推定 | 「インパクト = 再出現直前」は良い。「トップ = インパクトから実速 0.25〜0.3 秒前」は絶対時間で、焼き込みスロー動画（macroy は 4〜6 倍）では 1 秒以上ずれる。比で置くべき |
| P3 手首点の連続性 | これは入力の衛生として必要。ただし距離モデルの相対閾値（最大速度の 20% / 10%）が偽ピークに左右される構造は残る |
| 全体 | AGENTS.md §3.2「古い構成に継ぎ足さない」に反する。距離モデルの前提「手首が最後まで見える」が後方視点で偽である以上、前提を変えるべき |

## 4. 提案：手の高さモデル

### 4.1 信号

```
torso   = |neck.y − root.y| の動画全体での中央値（体の大きさ。1 フレームの外れ値に揺れない）
h(t)    = (wrist.y − root.y) / torso          … 手の高さ。腰の高さが 0、首の高さが 1
v(t)    = 手首の移動速度 / torso              … 体の大きさ単位の速度（1/秒）
```

root が欠けたフレームは直前の root を使う（腰はスイング中ほとんど動かない）。実測値：

| 動画 | torso | アドレス h | トップ h | インパクト h | フィニッシュ h | 腰・首の信頼度 |
| --- | --- | --- | --- | --- | --- | --- |
| macroy（後方） | 0.12 | −0.2 | 1.7（2 秒の静止） | 0.0 | 1.9 | 0.6〜0.8 |
| yuta（後方） | 0.17 | 0.1 | 1.3（静止中）／本番は未観測 | 未観測 | 1.7 | 0.5〜0.8（手首が消えている間も） |
| YTDown（正面） | 0.16 | −0.2 | 1.6 | −0.2 | 1.4 | 0.6〜0.8 |
| Golfboy（正面） | 0.38 | −0.2 | 0.7（手が頭の高さまで） | 0.05（再出現） | 0.7 | 腰 0.3〜0.4、首 0.5〜0.7 |

閾値：**低い = h < 0.3、高い = h ≥ 0.5**（アドレスの上限 0.1 と Golfboy のトップ 0.7 の間）。速度は同じ動画の中での比だけで使い
（アドレス = バックスイング最大の 15% 以下、切り返し = ダウンスイング最大の 30%、別のスイングのトップ = フォローの上がり以上）、**秒の閾値は持たない**
（動画の速さに依存しないため。欠測の判定 0.2 秒だけは解析フレーム 6 個の意味）。

### 4.2 フェーズの決め方

手が低い（h < 0.3）区間から順に「低い → 高い（h ≥ 0.5）→ 低い → 高い」の形を読み、成立した候補のフィニッシュより後の低い区間から続ける。
素振りも（フィニッシュを取っていれば）候補になり、採点で本番を選ぶ。

| フェーズ | 決め方 | 観測できないとき |
| --- | --- | --- |
| アドレス | 低い区間で最も低い高さの近く（0.1 以内）にいて、速度がバックスイングの最大の 15% 以下（まだ動き出していない）である最後の点 | 速度が落ち着かなければ高さだけで決める |
| トップ | 手が最も高い点の後、高さが下がりながら速度がダウンスイングの最大の 30% に達した点（切り返し）。トップで止まっても下ろし始めが取れる | 手首が消えた時点で既に高ければその時刻。まだ上がり途中なら、A + 0.75 × (I − A)（バックスイング : ダウンスイング = 3 : 1） |
| インパクト | トップの後、次に高くなるまでで h が最小の時刻 | 切り返しが欠測に掛かったら、再出現から次に高くなるまでの最低点（本当のインパクトは欠測の中かもしれないので推定扱い） |
| フィニッシュ | フォローで手が上がりきる山（そこから 0.3 下がるまで）の高さの 90% に最初に達した点 | — |

- **トップの静止・スローで伸びた切り返し**：h が高い領域に居続けるだけなので、区間が切れることも、アドレスに取られることもない
- **インパクト付近で手が止まって見える**（後方視点のスロー）：スイングの途中の低い区間は次のスイングの候補にしない（成立した候補のフィニッシュより後から読み直す）
- **素振りの直後の本番**：素振りがフィニッシュを取らずにアドレス位置へ戻ると、その次に高くなるのは本番のトップ。フォローの後に手が低く戻る速さが
  フォローで上がった速さ以上なら「別のスイングのトップ」とみなし、素振りは候補にしない（本番はその低い区間から別に読まれる）
- **採点**：現行の「移動量」を h_max − h_address（振り上げの大きさ）に置き換え、ピーク速度は v の最大（体の大きさ単位）。時系列順の加点は現行どおり
- **lowConfidence**：トップかインパクトを推定で置いたとき、または手首の検出率 40% 未満

### 4.4 入力の整え方（PoseTracker）

- `PoseTrack` に腰（root）と首（neck）の位置を持たせる（フレームごと・nil 可）。既存の `bodyBounds` はそのまま
- **手首点の連続性**：両手首が見えれば中点。片方だけのときは、その手首に直前の「手首→中点」ベクトルを足して中点相当にする
  （後方視点で 1 フレームに 0.05〜0.2 飛んで偽の速度になるのを防ぐ）
- **信頼度のヒステリシス**：新しく採用するときは 0.3 以上、直前の点から 0.1 以内で続いているなら 0.15 以上で採用
  （yuta のバックスイング後半 15.37〜15.60 秒は 0.10〜0.19 で位置は妥当だった。トップまでは届かないが欠測が 0.25 秒縮む）
- 3 点メディアンは残す

### 4.6 残る限界

- 手首が **最後まで** 見えない（フィニッシュも隠れる）動画は候補が作れない。フォールバックのまま
- 切り返しは手の高さの最大の 2〜3 フレーム後になる（速度がダウンスイングの 30% に達した点）。手が最も高い点より、下ろし始めの方が同期の区切りとして安定するため
- 3 : 1 の比はツアープロ〜一般的なアマチュアの範囲。Golfboy のような遅いダウンスイング（1.4 : 1）では 0.2 秒ずれるが、
  そこは現行でも欠測の端に置いていて同程度。フェーズ調整で直す前提は変わらない
- カメラが大きく傾いている動画では「高さ」が画像の y と一致しない。想定外とする（水平に構えるのが普通）
- 腰と首が同時に見えるフレームが 1 つも無い動画では体の大きさが取れず、検出失敗（フォールバック）になる
