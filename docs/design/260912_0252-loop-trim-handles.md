## 1. 何を解きたいか

ループ範囲はメニューの 3 択（スイング全体 / 区間のみ / ループしない）で、区間の境目はフェーズの位置に固定されている。
実際に見たい範囲はフェーズの境目と少しずれる：

- 切り返しを見たい：ダウンスイングのループにトップの数コマ前を含めたい
- リリースを見たい：「ダウンスイングのみ」はインパクトで終わるので、ボールが離れる数コマ後が見えない
- 長いアドレスを飛ばしたい：全体のループのうち構えている数十コマを省きたい
- 検出が数コマずれている（[TODO.md](../TODO.md) D）：フェーズを直すと同期の写像まで変わるが、見たいだけならループを広げれば済む

動画編集アプリ（CapCut）はカットを選ぶと両端に白い縦棒のつまみが出て、ドラッグで範囲を詰める。外側は暗くなり、枠線で 1 カットに見える。
この動きをシークバーに持ち込む。**区間を選んだらつまみが出て、端をコマ単位で動かせる。端は「トップ −3 コマ」のようにフェーズからのコマ数で読める。**

## 3. 案 A の詳細

### 3.1 見た目と寸法

| 要素 | 値 | 理由 |
| --- | --- | --- |
| つまみ | 12 × 32pt、白、角丸 3pt、中央に 1.5pt の暗い縦線 | CapCut と同じ記号。再生ヘッド（4pt 白）より太く、取り違えない |
| 位置 | 範囲の**外側**に接して置く（左は右端が開始位置、右は左端が終了位置） | 範囲の中の映像位置と再生ヘッドを隠さない。全体幅まで広げても `ControlPanelView` の横 padding 16pt に収まる |
| 当たり | 44 × 44pt（バーの上下に 8pt はみ出す） | HIG。上下の隣（基準の切り替え・フェーズジャンプ）とは spacing 8pt で接するだけ |
| 枠線 | 範囲の上下に 1.5pt の白 | 2 本のつまみを 1 つのカットに見せる |
| 範囲の外 | 黒 60% で沈める | 今の「選んだ区間以外を薄くする」の置き換え。区間の境目を越えた範囲でも意味が保てる |
| 読み出し | つまみの真上 10pt に白い吹き出し。太字「トップ −3 コマ」＋ 等幅の小さい「0.830 秒」。ドラッグ中だけ | 端を目で確かめられる。横位置はバーの幅に収める |
| 押している間 | つまみを黄色に | 写真アプリのトリマーと同じ。離すと白に戻る |

シークバーの高さ 28pt は変えない（つまみは上下に 2pt ずつはみ出す）。区間の色は常に 0.85（今は選んだ区間以外を 0.25 にしている）。

### 3.2 触り方

- メニューで「ダウンスイングのみ」を選ぶと、トップとインパクトの位置につまみが出る（今と同じ範囲でループが始まる）
- つまみをドラッグすると端が動く。**最も近いフェーズから整数コマ**（基準側動画の 1 フレーム）の位置にしか止まらない。
  秒の自由な位置は許さない（読み出しがコマで揃い、ジョグホイールと同じ物差しになる）
- 開始と終了は最低 1 コマ離す。範囲は 0〜共通タイムラインの長さに収める
- ドラッグ中は再生を止め、両方の映像を**つまみの位置のコマ**へシークして見せる（動画編集アプリの詰め方と同じ。端のコマを目で選べる）
- 離したら：再生中だったなら範囲の先頭から再開。止まっていたなら再生ヘッドは端に残す（そのままジョグホイールで端の前後を確かめられる）
- つまみ以外をドラッグすると今までどおりシーク。つまみの当たりが優先（`highPriorityGesture`。`PhaseEditView` のマーカーと同じ）
- メニューは変えない。つまみを動かすとチェックはどの項目にも付かないが、↻ のアイコンは「範囲あり」（`repeat.1`）のまま。
  「スイング全体」「ループしない」を選ぶとつまみは消える

### 3.3 触覚

ジョグホイールの 3 種類の語彙（[260911_0741](./260911_0741-jog-wheel-frame-stepping.md) §4）に合わせる。

| 出来事 | 感触 | API |
| --- | --- | --- |
| つまみが 1 コマ動いた | 軽いカチッ | `.sensoryFeedback(.selection, trigger:)` |
| フェーズにぴたりと乗った（コマ数 0） | 中くらいのドン | `.impact(weight: .medium)` |
| 反対側の端に当たった（1 コマ幅） | 重い止まり | `.impact(weight: .heavy)` |

ジョグホイールの「ループ範囲の端に当たった」の重い触覚は、新しい端でそのまま鳴る（`stepFrame` が `loopRange` で止めるため）。

## 4. 仕組み

### 4.1 端は「フェーズからのコマ数」で持つ

秒で持つと、フェーズ調整や基準の切り替えで共通タイムラインが伸縮したときに端がずれる（今の「区間のみ」はフェーズに追従する。それを失わない）。
端をフェーズと整数コマで表すと、共通タイムラインが変わっても `commonTime(of:)` から計算し直すだけで付いてくる。読み出しの文言もこの値そのもの。

```swift
/// ループ範囲の端。フェーズからのコマ数で持つので、フェーズ調整や基準の切り替えで区間が伸縮しても端が付いてくる
struct LoopEdge: Hashable {
    var phase: SwingPhase
    var frames: Int          // 基準側動画のコマ数。負なら手前

    var label: String        // 「トップ」「トップ −3 コマ」
}

enum LoopMode: Hashable {
    case all
    case range(start: LoopEdge, end: LoopEdge)
    case off

    static func segment(_ segment: SwingSegment) -> LoopMode   // 区間のみ（メニューの項目）
}
```

`SyncEngine` に足すもの（純関数）：

- `commonTime(of edge: LoopEdge) -> Double`：`commonTime(of: phase) + frames × referenceFrameDuration` を 0〜`commonDuration` に収める
- `loopEdge(nearest time: Double) -> LoopEdge`：最も近いフェーズを選び、そこからのコマ数に丸める
- `commonRange(from: LoopEdge, to: LoopEdge) -> ClosedRange<Double>`：終了は開始 + 1 コマ以上

基準を切り替えると `referenceFrameDuration` も変わる（別の動画の 1 コマ）ので、「トップ −3 コマ」は新しい基準側の 3 コマになる。それでよい。

### 4.2 PlaybackController

- `loopRange`：`.range` なら `sync.commonRange(from:to:)`。それ以外は今のまま
- `beginTrim(_:)` / `trim(_ edge: 開始 or 終了, to time: Double)` / `endTrim()` を足す。`beginScrub` / `endScrub` と同じ骨格
  - `trim`：`sync.loopEdge(nearest:)` で端を決め、反対側の端と 1 コマ以上離れるように詰め、`loop` を更新。時計をその端に置いてプレーヤーをシークする
  - シークのまとめ方はジョグホイールと同じ（時計はすぐ動かし、シーク中なら完了ハンドラで最新の位置へ 1 回だけ。`stepFrame` の仕組みを共通の private 関数に切り出す）
  - `endTrim`：再生中だったなら `play()`（範囲の先頭へ）。止まっていたなら何もしない
- `updateSync` は変えない（端がフェーズに紐づくので写像し直す必要がない）
- ループ範囲は保存しない（今と同じくセッション内の状態。クリップの JSON は変えない）

### 4.3 SeekBarView

- 区間の色は常に 0.85。`loopRange` の外側に黒 60% を重ねる（`.all` / `.off` では幅 0 になるので分岐しない）
- `.range` のときだけ、つまみ 2 本と上下の枠線を描く。つまみは 44 × 44pt の `contentShape` を持ち、`highPriorityGesture(DragGesture(minimumDistance: 0))` でバーのシークより優先
- 座標はバーの `coordinateSpace` に名前を付けて取る（`PhaseEditView` の `timeline` と同じ）
- 読み出しは `overlay(alignment: .top)` の吹き出し。ドラッグ中の端の `label` と秒を出す
- 触覚は View 側で、端の値が変わったときにコマ数 0 なら中、それ以外は軽く。反対側に当たった（値が変わらなかった）ときは重く（`JogWheelView` の `atEnd` と同じ判定）
- VoiceOver：つまみは `accessibilityLabel`「ループ開始」「ループ終了」、値は `label`、`accessibilityAdjustableAction` で ±1 コマ。
  E2E の識別子は `seekBar.loopStart` / `seekBar.loopEnd`

### 4.4 TransportControlsView

- `loopMenu` の項目は今のまま。区間の tag を `LoopMode.segment(segment)` に置き換える。アイコンは `.range` なら `repeat.1`
- 動かした後の範囲はシークバーが示す。メニューに「トップ −4 コマ 〜 インパクト +6 コマ」の行を出すかは後で決める（今回はやらない）

## 7. 決めてほしいこと

1. **A / B**。推奨は A（区間を選んだときだけ出す。既定の画面は変えない）
2. **端の単位**。推奨は「最も近いフェーズから整数コマ」。読み出しが「トップ −3 コマ」になり、ジョグホイールと同じ物差し
3. **ドラッグ中の映像**。推奨は「つまみの位置へシークして見せ、離したら再生中だったなら範囲の先頭から再開」

## 8. 採用（2026-09-12）

案 A を、端の単位はフェーズからの整数コマ、ドラッグ中はつまみの位置へシークして見せる方式で実装した。

- `Models/LoopRange.swift`：`LoopEdge`（フェーズ ＋ コマ数、読み出しの `label`）と `LoopRange`（開始・終了。`segment(_:)` で区間の両端、
  `move(_:to:in:)` で最も近いフェーズから整数コマに丸めて反対側と 1 コマ以上離す）。`SyncEngine` に `commonTime(of:)` / `loopEdge(nearest:)` /
  `commonRange(of:)` を足した。§4.1 の `LoopMode.range(start:end:)` は `LoopMode.range(LoopRange)` にした（端の組を 1 つの値にして添字で扱う）
- `PlaybackController`：`beginTrim` / `trim(_:to:)` / `endTrim`。`trim` は時計を端に置いてから `loop` を更新する（didSet が範囲外と見て先頭へ動かさないように）。
  コマ送りとつまみで共通のシークのまとめ方を `show(_:)` に切り出した。`updateSync` は変えていない（端がフェーズに紐づくので写像し直す必要がない）
- `SeekBarView`：範囲の外を黒 60% で沈め（全体 / ループしないでは幅 0 なので分岐なし）、`.range` のときだけ上下の枠線とつまみ 2 本を描く。
  つまみは指の位置ではなく**つかんだ時点の端 ＋ 指の移動量**で動かす（指の位置だと、つまみの中心と端の 6pt のずれで触った瞬間に 1 コマ跳ねる）。
  移動量はバーの名前付き座標系で測る（つまみ自身の座標系で測ると、つまみが指に付いて動くたびに移動量が縮んで戻り、コマごとに往復して発振する。実機で確認した不具合）。
  つまみと吹き出しは overlay の中の明示的な `ZStack` にしてバーの大きさに固定する（overlay の暗黙の ZStack は子を子の最大の大きさの中央に寄せるので、
  吹き出しが出た瞬間につまみが 48pt 右へずれ、離すと戻る。実機で確認し、同じ組み立てを macOS の `ImageRenderer` で描いて画素で再現・修正を確かめた）。
  読み出しは幅 140pt の吹き出しをバーの幅に収めて上に出す。触覚は §3.3 の 3 種類。重い触覚は「隙間が 2 コマ未満で、なお寄せようとしている」ときだけ
  （触った直後に指がまだ動いていないだけでは鳴らさない）
- `TransportControlsView`：メニューの項目は変えず、つまみで動かした範囲のときだけ「トップ −4 コマ 〜 インパクト +6 コマ」の行を足してチェックを付ける。
  §4.4 では後回しにしたが、`Picker` は選択が項目に無いと未定義になるので必要だった
- テスト：`SwingDuetTests/LoopRangeTests.swift`（最も近いフェーズからの丸め、端の収まり、区間との一致、1 コマ幅の詰め、丸めの食い込みの退き、
