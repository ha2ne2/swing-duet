# お手本の選び方の再設計：4 方向の案

- 日付：2026-09-06
- 種別：設計（コード変更なし）
- モック：https://claude.ai/code/artifact/dc05586c-370c-45fe-ac54-93c8c9f3cacf（iPhone 画面のモックを案ごとに 1 行に並べたキャンバス。各行の左に案の説明。1 行目が D）
- 対象：`NewComparisonView` / `ProjectListView` / `ComparisonView` / `ModelLibraryView` の遷移と情報構造

## 1. いまの問題

2026-09-06 に入れた「お手本の登録」（[SPEC.md](../SPEC.md) §2.1）は機能としては動くが、体験として次の問題がある。

- 「新しい比較」がフォーム（行 3 つ + トグル + 名前欄）で、**「登録」という概念を覚えないと使えない**
- 登録の入口が 3 か所（フォーム / 比較画面の ☆ / 一覧の ☆）に散っている
- 遷移が長い：一覧 → シート → ピッカー → シート → 解析 → 比較

## 2. 3 案に共通する原則

1. **「登録」という言葉と概念を消す**。お手本は集めるもの、名前は付けるもの。トグルは置かない
2. 最頻の操作「同じお手本に、自分の新しいスイングをぶつける」を**最短**にする
3. フォームの行ではなく、**サムネイルを直接選ぶ**。名前は 1 回だけ、その場で
4. **解析待ちは画面として見せる**（何を待っているか分かり、終わったら自動で比較へ）

## 3. 案

| 案 | 考え方 | 最頻操作 | トレードオフ |
| --- | --- | --- | --- |
| **A. お手本の棚** | ホームにお手本の棚（大きなカード）を置き、お手本を主役にする。追加は棚の「+」→ 写真 → 名前。解析は裏で走りカードに輪が回る | ホーム →「自分のスイングを選んで比較」→ ピッカー → 解析 → 比較（タップ 1 + ピッカー） | ホームが 2 層（棚 + 比較一覧）。お手本が 1 つの人には棚が大げさ |
| **B. まず自分のスイング** | 「+」で即ピッカー。自分を選んだ直後にお手本を大きなカードで選ぶ。前回のお手本が選ばれた状態で、ボタンが「〜と比較」と読める | + → ピッカー →「〜と比較」→ 解析 → 比較（タップ 2 + ピッカー） | 前回のお手本をそのまま使うときも選択画面が 1 枚はさまる |
| **C. 比較画面がすべて**（推し） | 「プロジェクト」も「登録」もやめる。ホームは自分のスイングの一覧。お手本は比較画面のチップから**その場で入れ替える**。追加・名前付け・解析待ちもその場 | + → ピッカー → 解析 → 比較（前回のお手本が自動。タップ 1 + ピッカー）。別のお手本はチップ → カード | データモデルが変わる（自分のスイング 1 本に対しお手本は参照。拡大・位置合わせはお手本ごとに保持）。実装は最大 |

## 3.5 D. 起動したら比較画面（ユーザー案）

起動時は再生メイン画面そのもの。動画は 2 つとも空で、ペイン中央の ○+ を押すとピッカー
（登録済みの一覧 + 「ライブラリから選ぶ」）。左右どちらのペインも同じピッカー。

- ライブラリから選ぶと解析はそのペインの中で進み、もう片方はその間に選べる。両方そろうと操作が有効になり、履歴に自動で残る（保存ボタンは無い）
- ツールバー：左「履歴」（過去の比較。タップで開き直す）、右「お手本」（登録済みの一覧。追加・名前変更・削除）
- 最頻操作：起動 → 右 ○+ → 前回のお手本 → 左 ○+ →「ライブラリから選ぶ」→ 解析 → 再生（タップ 4 + ピッカー）
- 長所：画面が 1 枚で状態が常に見える。比較画面が舞台
- 要判断：(1) 起動時に前回のお手本を右に入れておくと最頻操作がタップ 2 に減る（空から始めるのがユーザー案）。
  (2) ライブラリから選んだ動画を登録する入口（ペインのチップを長押し →「お手本に登録」を想定）

### 「登録」の呼び名の候補

| 候補 | 評価 |
| --- | --- |
| **お手本**（推し） | 短い。比較の相手＝手本という意味が自然で、友人のスイングも「比較の手本」と読める。右ペインのラベルと同じ言葉で揃う |
| 保存したスイング | 正確で中立。ボタンには長いので「保存済み」 |
| 比較相手 | プロも友人も含む。機能的だがやや硬い |
| スイング集 | 集める感じは出るが、何のためかが伝わりにくい |
| 見本 | 「お手本」より客観的。日常語としては弱い |

判断の軸：ボタンに載る短さ、右ペインのラベルとの整合。左ペインにも登録済みを入れる使い方を前面に出すなら「保存したスイング」か「比較相手」。

## 4. 推しと段階案

- **推しは C**。お手本は「比較の対象」であって「登録するもの」ではない、という製品の芯に一番近い。同じスイングを複数のお手本で見比べる用途にも強い
- 段階案：まず **B** でフォームを廃止して遷移を短くし（既存のデータモデルのまま）、次に **C** のチップ入れ替えを比較画面に足す

## 5. C を採る場合のデータモデルへの影響（実装時に設計する）

- `ComparisonProject`（自分 + お手本の複製）→ 「自分のスイング」1 本 + 選択中のお手本 ID + お手本ごとの位置合わせ、へ
- お手本の動画は複製せず 1 本を共有する（現状の「複製して参照を数えない」方針は捨てる）。削除時は参照しているスイングの扱いを決める
- フェーズ修正の反映先は自然にお手本 1 本に集約される（現状の同期処理は不要になる）

## 6. 決定（2026-09-06）

- **D 案を採用**して実装した。右上のボタンは「お手本を選ぶ」（右ペインの + と同じピッカー）
- 呼び名は「お手本」。ライブラリから右ペインに入れた動画は名前を付けて登録済みになる（左ペインは登録しない）
- 起動時は両ペインとも空（ユーザー案どおり）。前回のお手本をあらかじめ入れる案は見送り
