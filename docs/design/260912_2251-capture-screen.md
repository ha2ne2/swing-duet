## 0. 第 2 稿での変更（自己レビュー）

- **「見えています。録画を押したら…」をやめた。**枠に入るのは自分で、録画を押すときは枠の中にいない。準備では「見えている」は起きない。
  代わりに**録画を押して打席で構えたとき**に、全身が映っているかを音で知らせる（♪ 見えた / ♪♪ 切れている）。直すのは 1 往復で済む
- **背面カメラの画面はレンズの裏側で、打席から見えない。**初稿の「縁の色を 2〜4 m から見る」は成り立たない。合図は音が主で、縁の色と大きな球数は
  近づいたとき（と前面カメラのとき）のもの。音はマナーモードでも鳴らし、アプリの中で切る（§8 の 2）
- **前面カメラ（120fps）を「やらない」から「選べる」に。**打席から画面が見えるのは前面カメラだけ。240fps か、画面が見える 120fps か、選べるようにする（§8 の 7）
- **入口は B（2 カプセル）に決定（2026-09-13）。**「撮影」と「ライブラリから」を、同じ見た目のカプセルで下端に並べる。どちらもスイングを足す入口で、主従を付けない。
  丸いボタン 1 つ（B′）とタブ（C）との比較は §2.1 に残す
- 人物の周りの薄い枠（位置合わせ用）を消した。準備では誰も写っておらず、打席からは見えない

## 1. 使う場面と、そこから決まること

一人。打ちっぱなしの打席。iPhone は三脚で打席の後ろ（後方視点）か横（正面）、打つ人から 2〜4 m。録画を押したら打席に戻り、
以後 30〜60 分・50〜100 球、iPhone には触らない。素振り・空振り・球拾いが混ざる。

| 場面の事実 | 画面に求めること |
| --- | --- |
| 枠に入るのは自分。押すときは枠の中にいない | 準備で「見えています」は起きない。**録画を押して打席で構えたとき**に全身が映っているかを音で知らせる（♪ 見えた / ♪♪ 切れている）。直すのは 1 往復 |
| 背面カメラの画面はレンズの裏側。打席から見えない | 打席に届く合図は**音**だけ（見えた / 切れている / 取れた / 止まった の 4 つ）。縁の色と大きな数字は近づいたときに一目で分かるためのもの。前面カメラ（120fps）なら打席から画面が見える（§3 の注） |
| 手が塞がっている（グローブ・クラブ） | 撮影中に操作はさせない。近づいてする操作は「止める」「最後の 1 球を見る・消す」だけ |
| 屋外・日中 | 白と黒のコントラストで作る。半透明の薄い表示は見えない |
| 30〜60 分つけっぱなし | 画面は消さない（`isIdleTimerDisabled`）。熱・電池・容量を見張り、落とすときは縁を橙にし、止めたときは音で知らせる |
| 隣の打席がある | 音は短い電子音だけ。音量は本体の音量。「…」で切れる。話す合図（球数の読み上げ）はしない |
| 素振り・空振り・球拾い | 素振りは残さない（分割エンジンの規則。§4）。誤検出はその場で消せる |
| 打った直後に「今のどうだった」 | 最後の 1 球はその場で見られる（リプレイ）。お手本との比較はホームに戻ってから |

## 2. 画面の流れ

ホーム（下端の「撮影」カプセル）→ 撮影画面（準備：三脚を置いて録画を押し、打席へ → 録画中：構えると ♪、ショットごとに ♪ と ＋1）→ 止める → ホーム（今日の節に 1 球ずつ並び、上から解析）→ 行 → ステージ（今と同じ）

撮影画面は `fullScreenCover`（縦横どちらでも使えるように。ステージと同じ）。止めたら閉じてホームに戻る。撮影中に帯のサムネイルをタップするとリプレイが重なる（§3 の 5）。

## 3. 撮影画面の 7 つの状態

全面がプレビュー。打席に届くのは音（♪ 見えた / ♪♪ 切れている / ♪ 取れた / ♪ー 止まった）。
画面は**縁の色**（灰 = まだ見えていない、緑 = 見えている、白の点滅 = ショット、橙 = 警告）と**大きな球数**（74pt）で、近づいたときに一目で分かる。
文字はその補足で、縁の色と同じことを言う。上に「✕」「● 経過時間」「240 fps」「…」、下に取れたショットの帯（右が新しい）と録画ボタン。

| 状態 | 見え方 | 補足 |
| --- | --- | --- |
| 1 準備：三脚を置く | 誰も写っていない。縁は灰色。録画ボタンは白い輪。「録画を押して打席へ。構えると音で知らせます」 | 打席にマットが入るように三脚を向け、録画を押して打席へ。「見えています」はここでは起きない |
| 2 録画中：構えたら ♪ | 打席で構えて 2 秒静止すると判定。全身が映っていれば ♪ と縁が緑（「見えています」）。足元や頭が切れていれば ♪♪ と縁が橙（「足元が切れています」） | 歩いて入る途中は判定しない（手が低く静かになってから）。直すのは 1 往復で済む |
| 3 録画中：待ち | 縁は緑。大きな球数「11 球」。上に「● 12:34」。帯にサムネイル。録画ボタンは赤い ■ | 球数は近づいたとき一目で（前面カメラなら打席から）。経過時間は小さくてよい |
| 4 ショットの直後 | ♪ 取れた。画面では縁が白く光り「＋1」、消えると球数は増えている。帯の右端に「切り出し中」の枠 → 数秒でサムネイル | 打席にはこの音だけが届く。打ってから 8 秒後（2 球目以降は 3 秒後。§4） |
| 5 帯をタップ：リプレイ | そのショットを 1/8 のループで大きく。「削除」「閉じる」。上に「● 録画は続いています」 | 誤検出（空振り・隣の人）をその場で捨てる。比較はしない。閉じると 3 に戻る |
| 6 警告 | 縁が橙。帯「本体が熱いので 120fps に落としました。冷えれば 240fps に戻ります」 | 撮影は止めない（音も鳴らさない）。空き容量 2 GB 未満・電池 10% 未満・5 分誰もいないときは ♪ー と鳴らして止め、保存してホームの帯に理由を出す |
| 7 止めた後：ホーム | 今日の節に 42 行。「42 球を保存しました 13:02–14:01」。行は仮のフェーズで開ける状態、上から「解析中…」 | 下端は「撮影」「ライブラリから」の同じ見た目のカプセル 2 つ（B） |

前面カメラ（120fps）：「…」で切り替える。プレビューは鏡像で、打席から縁の色と球数が見える（音はそのまま鳴る）。構えの位置を画面で直せるので、1 往復も要らない。
横向き：端末を横にすると縁と数字はそのまま、録画ボタンと帯は右の列に移る（カメラアプリと同じ）。動画の向きは録画を始めた時点の向きで固定し（`preferredTransform`）、途中で回しても変えない。

## 4. ショットが出来るまで（ライブ検出の規則）

分割エンジン（`ShotSplitter`）の規則は「候補どうしが 6 秒以内なら同じ組、組の中で明らかに小さいものは素振り」。撮影中にこの規則をそのまま使うには、
**フィニッシュ（F）から 6 秒、もっと振り切った候補が来ないことを待つ**必要がある。ただし保存と合図は判定を待たない（2026-09-13 に変更。§9）：
候補が見つかった時点で合図を鳴らし、区切りファイルが閉じたらすぐ切り出してアプリ内のファイルとして一覧に出す。判定は「写真ライブラリに移す」か「消す」かを決めるだけ。

| 時刻 | 起きること | 打席に届く合図（近づいたときの画面） |
| --- | --- | --- |
| F + 1 秒 | 15fps の追跡（`PoseTracker.FrameTracker`）から、直近 8 秒の窓に 0.5 秒ごとに `SwingDetector.detect`。フィニッシュの 1 秒後に形が安定して候補として登録 | **♪ 取れた**（縁が白く光り「＋1」。球数はここで増える。帯の右端に「切り出し中」の枠） |
| F + 1.6 秒 | 後ろの余白（1.5 秒）が書き終わったので、手が低く静かなら区切りファイルを閉じ、次のファイルへ（フレームは落とさない。design/260912_1951 §4.2） | 無し |
| F + 2.5 秒 | 閉じたファイルからアドレス −1.5 秒〜F +1.5 秒（`leadIn` / `leadOut`）を `VideoImporter.exportSegment`（パススルー）で切り出し、アプリ内のファイルの仮のクリップにする | 帯にサムネイル |
| F + 6 秒 | 組の規則で判定。本番なら写真ライブラリのアルバム「SwingDuet」に移して参照にする。素振りならクリップとファイルを消す | 素振りなら帯から消え、球数が減る |

- **早める余地**：そのセッションで 2 球以上決まった後は、その中央値の 6 割以上の振り上げ・速さなら判定を待たない（F + 1 秒）。
  本番の後に素振りが来ることは稀で、来ても後解析と同じ規則（中央値の 6 割未満）で捨てられる
- **下限**：切り出す範囲がフィニッシュの 1.5 秒後までなので、どんな仕組みでも保存は F + 2.5 秒前後より早くならない。合図は F + 1 秒で固定。
  素振りにも合図が鳴る（自分で素振りしたと分かっているので害は無い）。写真ライブラリには素振りが残らず、消すのに OS の確認も出ない
- **切り出したショットのフェーズ**：ライブ追跡（15fps）の切り抜きに `SwingDetector` を掛けて仮のフェーズを付け、クリップは `done` ですぐ開ける状態にする
  （長い動画の分割で `sliced(to:)` がしていることと同じ。分解能は 1/15 秒）。止めた後に既存の解析キューが 30fps で解析し直して置き換える
  （撮影中は Vision を取り合わないので回さない）
- **1 ショットの大きさ**：切り出す範囲は 4.4 秒前後（本番 1.4 秒 ＋ 余白 3 秒）。カメラアプリ相当の 64 Mbps なら 35 MB、100 球で 3.5 GB。ビットレートとキーフレーム間隔は実測で決める（§5.1）

## 5. 仕組み

```
撮影        背面 1x 1920×1080・240fps（AVCaptureDevice.Format）
            → AVCaptureVideoDataOutput（1 枚ずつ 2 か所へ）
              → AVAssetWriter（HEVC・区切りファイル）
              → 240 → 15fps に間引き → PoseTracker.FrameTracker → 直近 8 秒の窓に SwingDetector.detect → ShotSplitter の規則で判定（F + 6 秒）
            → AVCaptureVideoPreviewLayer（縁・数字・帯を重ねる）
ショット    閉じたファイルから VideoImporter.exportSegment → PhotoLibrary.saveVideo（アルバム SwingDuet）→ ClipStore に参照のクリップ（仮のフェーズ）
            → 止めた後、既存の解析キューが 30fps で解析し直す
```

新しく書くのは「撮影」（セッション・書き込み・間引き・プレビュー）と「判定」「ショット」の流れ。追跡・検出・切り出し・保存は長い動画の分割で作った部品をそのまま使う。
外部依存は増えない（AVFoundation・Vision・Photos）。

### 5.1 調べたこと（API と制約）

| 項目 | 分かったこと | 設計への反映 |
| --- | --- | --- |
| 録画と検出の 2 出力 | iOS 16 以降にリンクしたアプリでは `AVCaptureMovieFileOutput` と `AVCaptureVideoDataOutput` を同じセッションで同時に使える（SDK ヘッダ）。ただし `hardwareCost` が 1.0 を超えると始まらず、フレームレートは `AVCaptureDevice` 側で 1 つ（出力ごとに 15fps にはできない）。iOS の `startRecording(to:)` は録画中に呼べず、ファイルの切り替えで途切れる | 書き込みは案 B どおり `AVAssetWriter`（区切りの切り替えが途切れない、エンコード設定を持てる）。15fps への間引きは delegate で自前。実機で 240fps が落ちるなら MovieFileOutput ＋ データ出力に落とす手がある（区切りの切り替えは手が静かなときなので、途切れは害が無い） |
| 1080p240 のフォーマット | iPhone 15 は背面 1080p 120 / 240fps、前面 1080p 120fps（Apple の仕様）。どの `AVCaptureDevice.Format` かは実機で `formats` を列挙して確かめる（**未確認**）。`activeFormat` を設定するとプリセットは `.inputPriority` になる。1080p240 は H.264 不可で HEVC | 段階 1 で実機で列挙する。超広角（0.5x）は 240fps 非対応の前提で背面 1x のみ |
| データ出力 → AVAssetWriter で 240fps | 画素形式は 420v（BGRA は 2.6 倍のメモリ。TN3121）。`alwaysDiscardsLateVideoFrames = false`、`expectsMediaDataInRealTime = true`。`recommendedVideoSettings(forVideoCodecType:assetWriterOutputFileType:)` がカメラアプリと同じ設定。30fps 超では `AVVideoExpectedSourceFrameRateKey` を入れないとエンコーダがコマを落とす。`kVTCompressionPropertyKey_RealTime` は `AVVideoCompressionPropertiesKey` に入れる（`AVVideoEncoderSpecificationKey` は macOS 専用）。プレビューの描画が重いと 240fps が出ない | この設定で始め、段階 1 で実機でコマ落ち（時刻の飛び）を数える |
| キーフレーム間隔 | 設計書の 15 フレームは 240fps では毎秒 16 枚の I フレーム。Apple のエンジニアは 120fps の 20 フレームでも「毎秒 1 枚の 6 倍のデータ量」と指摘。HEVC でも `AVVideoMaxKeyFrameIntervalKey` は効く模様（ヘッダの注記は H.264。**未確認**） | 15 / 30 / 60 を実機で測って決める。基準は 1 ショットの大きさと、戻る操作の絵の更新（TODO I）。切り出しの端は編集リストで隠れるので粒度は問題にならない |
| 容量 | カメラアプリの 1080p240 HEVC は約 480 MB/分（≈ 64 Mbps。第三者の記事。Apple の公式値は設定アプリの画面の中だけ） | 区切り 1 本（≤ 60 秒）≈ 480 MB、1 ショット 4.4 秒 ≈ 35 MB、100 球 ≈ 3.5 GB。始める条件「空き 2 GB」はこの値で見直す |
| 写真アプリでの「スロー」扱い | `videoHighFrameRate` はカメラアプリの Slo-mo だけで、アプリからは付けられない（`PHAssetChangeRequest` に無い）。iOS 18 の `quickTimeMetadataKeyFullFrameRatePlaybackIntent` は「実速で再生する」印。サードパーティの 240fps が Slo-mo アルバムに入るかは**未確認**。100fps 超の保存で `performChanges` が失敗した報告（2019 年、未回答） | 撮ったショットは写真アプリでは実速で再生される（アプリはフレームレートを読むので影響なし。「動画」タブのスローの印は付かない）。保存は段階 1 で実機で確かめる |
| 熱 | `AVCaptureDevice.systemPressureState`（nominal / fair / serious / critical / shutdown。要因に温度とピーク電力）を KVO し、下げるならフレームレート（ヘッダの推奨。AVCam は serious 以上で 15〜20fps に）。`ProcessInfo.thermalState` はカメラ固有の要因を含まない。shutdown でセッションが中断される | serious で追跡を 10fps に、critical で 120fps に落として縁を橙、shutdown は止めて保存（§3 の 6）。設計書 §4.7 の `ProcessInfo.thermalState` を置き換える |
| 向き | iOS 17 の `AVCaptureDevice.RotationCoordinator`（プレビュー用と記録用の角度）。データ出力の接続に角度を設定するとフレームの配信が途切れる（WWDC23）ので、Vision には `orientation` で渡し、書き込みは writer input の `transform` に開始時の角度を書く | 動画の向きは開始時に固定（§3）。物理回転はせずメタデータだけ（今の取り込みと同じ扱い） |
| Vision の速さ | 公式の数値なし。iPhone 13 以降で 1 枚 8〜12 ms（Neural Engine。実装者の計測。A16 は**未確認**）。並列に投げても速くならない | 15fps なら 1 枚あたり 67 ms のうち 10 ms 前後。1 本の直列キューで、追い付かなければ遅れたフレームを捨てる |
| 中断と背景 | 背景ではカメラを使えず、セッションが中断される（電話・アラーム・iPad の複数アプリも）。`AVAssetWriter` は背景に入る前に `finishWriting` しないとファイルが壊れる（-11847） | 中断・背景・電話では区切りを閉じ、切り出し待ちを片付けてから止め、ホームに理由を出す。`isIdleTimerDisabled` は撮影画面にいる間だけ |

## 7. 段階

1. **骨格**：撮影画面（準備・録画・止める）、240fps の書き込み（区切りなしの 1 ファイル）。止めたら長い動画として写真ライブラリに保存し、
   既存の分割（`ClipStore.split`）が 1 球ずつにする。ライブ検出なし。撮影の設定（フォーマット・向き・エンコード・保存）を実機で確かめる。
   5 分までのセッションなら容量も待ち時間も許容できる。実機で確かめること：フォーマットの列挙、コマ落ち、240fps の写真ライブラリへの保存、キーフレーム間隔ごとの大きさ（§5.1）
2. **ライブ検出と区切り**：15fps の追跡、区切りファイル、F + 6 秒の判定、切り出し、帯と「＋1」、4 つの音（見えた / 切れている / 取れた / 止まった）、仮のフェーズ。
   容量が 1 区切り分に収まり、打った数秒後にショットが出る
3. **仕上げ**：リプレイ、熱・電池・容量の見張りと 120fps への切り替え、自動停止、横向き、前面カメラ、解析し直し

## 8. 決めてほしいこと

1. **入口**：**B に決定（2026-09-13）**。ホームの下端に「撮影」「ライブラリから」を同じ見た目のカプセルで並べる。主従を付けない。C（タブ）は撮影が「場所」になるときのもの（§2.1）
2. **打席に届く合図**：音を主にする（推し）。4 つ（♪ 見えた / ♪♪ 切れている / ♪ 取れた / ♪ー 止まった）。マナーモードでも鳴らし、切るのはアプリの「…」。縁の色と大きな球数は近づいたときのもの
3. **ショットの判定の待ち**：F + 6 秒で決める（推し）。素振りを残さない規則を後解析と揃える。2 球以上決まったら中央値で早める（F + 1 秒）。即決（絶対の閾値）は素振りが混ざる
4. **止めた後の行き先**：ホームの今日の節（推し）。「42 球を保存しました」を下端に出す。まとめ画面や選別画面は作らない（帯で消せる。ホームでも消せる）
5. **切り出したショットの解析**：ライブ追跡から仮のフェーズを付けてすぐ開ける状態にし、止めた後に 30fps で解析し直す（推し）。
   止めた後の解析だけにすると、撮影中はリプレイもサムネイルもインパクトの位置が分からない
6. **その場の確認**：帯のサムネイルをタップでリプレイ（1/8 のループ）、「削除」と「閉じる」だけ（推し）。録画は続く。自動リプレイはしない

   240fps の細かさか、見える画面か。「…」はカメラ・240 / 120・音の 3 つだけ
8. **自動停止**：人物が 5 分いなければ止めて保存する（推し）。球を拾いに行く・休憩で忘れたときの電池と熱のため。止まっていたことはホームの帯で分かる
