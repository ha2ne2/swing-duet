# 責務と編集範囲を明確にする構造整理

## 目的

画面から保存・解析・撮影へ処理を追うときに、目的のファイルと変更される値がすぐ分かる構造にする。
画面の操作と検出の計算は維持し、既存の保存データを引き続き読めるようにする。

## 方針

- `Services` を `Analysis`・`Library`・`Media`・`Playback`・`Capture` に分ける。モデルは小規模なため直下に保ち、
  `Library`、`Pairing`、`VideoSource`、`SwingAnalysisResult` など、独立した役割を持つ型を同名のファイルへ置く。
  ファイルと日付の汎用拡張は `Support` にまとめる。特定画面専用の View はその画面のフォルダに置く。
- `ClipStore` はクリップの操作と解析キューを担当し、JSON の読み書き・退避と管理動画のファイル操作は `LibraryFiles` に委ねる。
  ファイル操作と業務上の削除判断を分け、保存形式の変換は `Library` 自身に置く。
- 動画の位置合わせを `PaneTransform` としてまとめる。比較画面は動画設定全体の Binding を渡さず、
  位置合わせの Binding とフェーズ保存の操作を分ける。相手側の位置合わせはスイングの `Pairing` が所有する。
  これにより、表示操作が最新の解析結果を上書きしないことを API の形で示す。
- `CaptureController` 内のフレーム処理と姿勢追跡を `CaptureFrameWriter`・`CapturePoseProcessor` へ分ける。
  キューの受け渡しと停止時の待ち合わせは維持し、単なる行数削減のための extension 分割はしない。
- コメントは型の責務、単位、所有権、失敗時の制約を中心にする。コードの読み上げ、移行経緯、長い操作説明は削る。
  数値の根拠、並行性・データ保護の理由は残す。

## 保存と検証

位置合わせはコード上でまとめるが、JSON の `scale` / `offsetX` / `offsetY` は同じ階層で読み書きする。
保存形式の版は変えず、旧形式の読み込みと旧キーでの書き出しをテストする。
位置合わせ・フェーズの編集が相手の変換や解析結果を巻き戻さないことも固定する。
全単体テスト、シミュレータ・実機向けビルド、解析 CLI のビルドとサンプル比較で確認する。
ファイル移動に伴うガイド・スクリプト・構成説明も同時に更新する。
