# インパクト前後で手の軌跡が凹む動画の原因

種別：調査。実機で「インパクトの後、本来は楕円を描くはずの手の軌跡が凹んだ動きになる」という報告を受けての原因調査。
**コード・設定は変更していない。**

## 結論

**姿勢推定の問題で、描画側の問題ではない。いまは対処を入れないことを勧める。**

この撮り方（後方から近め）ではダウンスイング中に手が体の陰に入る。そのとき Vision は
**左股関節の上に手首があることにして返す**。股関節はほとんど動かないので、手首も止まったままになる。
本来ならこの間に手は体の外側へ大きく振り出されるので、その膨らみが軌跡から丸ごと抜け落ち、
代わりに股関節のところに「止まった点」が残る。これが凹んで見える正体。

対処を勧めない理由は §4。安く効く見分け方がどれも成立せず、唯一効くものは**この 1 本だけを根拠に**
区間まるごとを捨てる判断になるため。

## 2. なぜ落とせないか（試した見分け方）

| 見分け方 | 結果 |
| --- | --- |
| 信頼度 | **不可**。この 5 コマは 0.32〜0.45 で、しきい値 0.3 を超えている。直後の正しい点も 0.44〜0.53 で差が無い |
| 股関節に近すぎる | **不可**。正常な動画でも手首が股関節に重なる瞬間はある（`yuta_202609` で 0.02、`マキロイ正面` で 0.05 体分） |
| 1 コマの速さが遅い | **不可**。正常な動画でもトップ直後などに 0.00 体分/秒のコマが出る |
| 止まりが続くコマ数 | **不可**。この動画は 3 コマ続きだが、`IMG_0173`（正常）もトップ〜インパクトで 3 コマ続く |
| 区間全体の速さ | **可能だが根拠が弱い**。下表のとおり 1 桁違う。ただし判断材料はこの 1 本だけ |

トップ〜インパクトの手の速さ（体の大きさ/秒）：

| 動画 | 中央値 | 動画 | 中央値 |
| --- | ---: | --- | ---: |
| **報告動画** | **0.15** | Golfboy | 8.00 |
| IMG_0173 | 0.97 | Shorts | 19.58 |
| macroy_behind | 1.55 | IMG_0172 | 5.58 |
| マキロイ正面 | 1.99 | yuta_202609 | 2.10 |

報告動画は「トップ〜インパクトの 4 ステップ中 3 つが止まり」＝ 75%。`IMG_0173` は 30 ステップ中 3 つ＝ 10%。
**区間に占める割合**なら分かれるが、しきい値を決める材料が 1 本しかない。

## 3. 見え方への影響

軌跡は測定点を忠実に描くので、フォローの線は「股関節の上の止まった点」から始まり、そこから真上へ跳ねる。
本来の楕円のうち**体の外側へ膨らむ部分（インパクト前後）が丸ごと欠けている**ので、内側にへこんだ形に見える。

なお、この 5 コマは検出（`SwingDetector`）も同じ点を見ている。フェーズの位置は目視では妥当だったが、
手首が止まったまま判定されている点は頭に入れておく必要がある。

## 4. 対処を勧めない理由

1. **安い見分け方が全滅している**（§2）。唯一効く「区間全体の速さ」は、しきい値の根拠がこの 1 本しかない。
   `IMG_0173` は 10% で、報告動画は 75%。その間のどこに線を引くかを決める材料が無い
2. **効かせる場所に設計変更が要る。** 判定にはフェーズ（トップ・インパクト）が必要だが、
   `JointTrails` はフェーズを知らない。作るときに掛けると保存内容が変わり、`currentVersion` を上げて
   全クリップの軌跡を作り直すことになる。描くときに掛けるならフェーズを渡す配線が要る
3. **根っこは姿勢推定側**。表示側で消しても、欠けた区間が空白になるだけで楕円は戻らない
   （消すこと自体は「無いものを描かない」ぶん凹みよりマシだが、直ったことにはならない）
4. **9 本中 1 本**。他の動画では起きていない

## 5. 再検討する条件

- **同じ撮り方でもう数本、同じ症状が出たとき。** そのときは「トップ〜インパクトの大半で手が止まっている区間は描かない」を
  描画側（フェーズを渡す）で入れる。区間まるごとを空白にするので、凹みではなく欠けとして見える
- 根本的には、手が体の陰に入っている間の手首を「止まった推定で埋める」のをやめたい。
  ただし `PoseTracker` の手首はフェーズ検出の入力でもあるので、変えるならフェーズ検出への影響を必ず測る
  （過去のリファクタでは検出結果のバイト一致を確認している）
