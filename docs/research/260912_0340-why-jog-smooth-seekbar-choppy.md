# なぜジョグは軽快で、シークバーで戻るとカクつくのか（図解）

**作成日時**: 2026-09-12 03:40 JST
**種別**: 調査（説明。数字の出典は [260912_0249](./260912_0249-seekbar-backward-scrub-stutter.md)、対策の比較は [260912_0319](./260912_0319-scrub-friendly-media-options.md)）

---

## 1. ひとことで

「戻る」シークが遅いのは、ジョグでもシークバーでも同じ（Mac で 1 回 24〜34ms。前進は 3ms）。
違うのは **シークの出し方** だけ。

- **ジョグ**は、1 回のシークが終わるのを待ってから次を出す。だから出したシークは全部絵になる
- **シークバー**は、指が動くたび（60Hz = 16ms ごと）に待たずに出す。`AVPlayer` は新しいシークが来ると
  **作りかけを捨てて最初からやり直す**。戻るシークは 16ms では終わらないので、指が動いている間は捨てられ続けて絵が出ない

前進は 3ms で終わるので、16ms ごとに出しても次が来る前に必ず終わる。だから前進だけ滑らか。

---

## 2. 前提：動画は「戻る」のが苦手

動画は「完全な絵（キーフレーム）1 枚 ＋ そこからの差分」の繰り返しで保存されている。
YouTube 由来のお手本は 120〜160 コマに 1 枚、iPhone で撮った動画は約 1 秒に 1 枚（240fps のスロー原本なら 235 コマに 1 枚）。

```
キーフレーム   差分  差分  差分  差分  差分  差分 ...（120〜235 コマ続く）
    [I]        [P]   [P]   [P]   [P]   [P]   [P]
                                  ▲
                              いまここ

前へ 1 コマ  ：次の [P] を 1 枚足すだけ                       → 3ms
後ろへ 1 コマ：[I] まで戻って [P] を積み直す（遠いほど遅い） → 24〜34ms、最大 50ms
```

---

## 3. ジョグ：終わるのを待って次を出す（`stepFrame`）

1 目盛りごとに時計（`commonTime`）はすぐ動かすが、プレーヤーへのシークは**前のが終わってから最新の位置へ 1 回だけ**出す
（[ARCHITECTURE.md](../ARCHITECTURE.md) §4）。

```
指（目盛り）   ●        ●        ●        ●          ← ふつうに回す（約 33ms ごと）
シーク         [=====]  [=====]  [=====]  [=====]     ← 1 本ずつ、30ms で完了
絵                   ✓        ✓        ✓        ✓   ← 出したシークは全部絵になる

指（目盛り）   ● ● ●  ● ● ●  ● ● ●                  ← 速く回す（目盛りがシークより速い）
シーク         [=====][=====][=====]                  ← 溜まった 3 コマ分を「最新の位置へ 1 回」
絵                   ✓      ✓      ✓                  ← 3 コマ飛ぶが、一定の間隔で更新される
```

- **速い**：無駄になるシークが 1 本もない
- **滑らか**：絵の更新が復号の速さ（30ms なら 33fps）で一定に来る。飛ぶコマ数は増えても間隔は変わらない

---

## 4. シークバー：待たずに出す（`scrub`）

指が動くたびに、前のシークが終わっていなくても新しいシークを出す。

```
【前進】 1 回 3ms  → 次のイベント（16ms 後）より先に終わる
指          ●               ●               ●               ●
シーク      [=]             [=]             [=]             [=]
絵            ✓               ✓               ✓               ✓    ← 毎回出る（滑らか）

【後退】 1 回 30ms → 16ms では途中。新しいシークが来て作りかけを捨てる
指          ●               ●               ●               ●          ●（止める）
シーク      [========x      [========x      [========x      [========x [==========]
                     ↑捨てる          ↑捨てる          ↑捨てる          ↑捨てる          ✓
絵          （指が動いている間は 1 枚も出ない）                                   ← 止めた瞬間だけ飛ぶ
```

「x」は取り消し。途中まで復号した分も捨てられるので、連射している限り絵が出ない。
指を少しゆっくり動かして、たまたま 30ms 空いたときだけ 1 枚出る。これが「カクカク」の正体。

---

## 5. 数字で見る（Mac M4。実機の A16 は復号が遅いのでさらに悪い）

Mac 上で `AVPlayer` に同じ出し方をさせ、60 回のシークのうち完了した数と、実際に出た絵の枚数を数えた
（お手本「マキロイ ドライバー」、キーフレーム間隔 160 コマ）。

| 出し方 | 向き | 完了 / 60 回 | 絵の更新 |
| ------ | ---- | ------------ | -------- |
| シークバー方式（16ms ごとに連射） | 前進 | 60 | 40fps（イベントの速さそのもの） |
| シークバー方式（16ms ごとに連射） | **後退** | **17** | **11fps** |
| ジョグ方式（終わってから次） | 後退 | 32（出した分は全部） | 21fps（復号の速さそのもの） |

シークバー方式でも、キーフレーム間隔が短い iPhone 撮影のスイング（29 コマに 1 枚、後退 8ms）なら 60 回とも完了する。
お手本（YouTube 由来）や 240fps のスロー原本のように、キーフレームが遠い動画で起きる。

---

## 6. どう直すか

1. **出し方を揃える**：シークバーもジョグと同じ「終わってから最新の位置へ 1 回」にする。取り消しが 0 になり、
   後退の絵の更新は復号の速さ（上の表の 21fps）まで戻る。ただしそれが上限
2. **「戻る」そのものを速くする**：取り込み時にキーフレームを 8〜15 コマごとに打ち直す（HEVC で再エンコード）。
   後退が前進と同じ 5〜10ms になり、1 と合わせて 60Hz でも取り消し 0

どちらも要る理由と、再エンコードのサイズ・画質・所要時間の実測は [260912_0319](./260912_0319-scrub-friendly-media-options.md)。
