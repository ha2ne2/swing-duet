## 4. 発見事項

### 4.1 PhotosPicker とスローモーション動画

投入した 240fps の動画（3.0 秒、725 KB）を「自分」に選んだところ、アプリの `Documents/Videos/` に保存されたのは
**30fps・14.67 秒・1,017 KB** の別ファイルだった（`AVAssetTrack.nominalFrameRate` = 30、`duration` = 14.67）。

- 写真アプリは 240fps 動画を「スローモーションビデオ」として扱い（ピッカーのセルもそう表示される）、
  `FileRepresentation(contentType: .movie)` の転送では **スロー効果を適用してレンダリングした現行バージョン**が渡される
- 60fps の動画は 3.0 秒・60fps のまま渡された（通常動画は無変換）
- 影響: 「240fps のスロー動画に対応」「コマ送りは実フレームレート単位」の前提が成り立たない。
  さらにスロー効果は動画の中盤だけに掛かるため、区間の時間比（テンポ比）も元動画と変わってしまう
- 対策案: PhotoKit で元ファイルを取得する（[TODO.md](../TODO.md) A）。写真ライブラリ権限が必要

### 4.2 Vision の姿勢推定はシミュレータで動作しない

解析中に以下がフレームごとに出力され、`VNDetectHumanBodyPoseRequest` は結果を返さなかった:

```
[com.apple.espresso:espresso] [Espresso::handle_ex_plan] exception=Espresso exception: "I/O error": Missing weights path cnn_human_pose.espresso.weights status=-2
```

- 実サンプル（実写）でも同じエラーで検出できず、フォールバックになった。合成動画（棒人間）の問題ではなく、シミュレータにモデル重みが無いことが原因
- アプリ側は `try?` で握りつぶし、フォールバック位相（15% / 45% / 55% / 85%、テンポ 3.0 : 1）と「信頼度が低い」警告で継続した。
  この経路が正しく動くことは確認できた
- 検出精度の評価は実機で `docs/data/` の実スイング動画を使って行う（[ROADMAP.md](../ROADMAP.md) フェーズ 2）
