# 検証動画と実機の手の軌跡が異なる原因

本書はバックスイング限定だった時点の調査記録。調査後、全3区間の近似とオン・オフを実装した。
現行仕様は [ARCHITECTURE §7](../ARCHITECTURE.md#7-関節の軌跡jointtrails) を参照。

## 結論

主因は、**検証動画は全3区間に6制御点近似を適用していたが、アプリはバックスイングだけに適用していること**。
バックスイングは滑らかで、トップ以降に揺れが残るという実機画像の状態は、この実装と整合する。

| 区間 | 検証動画の右側 | 現在のアプリ |
| --- | --- | --- |
| アドレス〜トップ | 6制御点で区間全体を近似 | 同方式 |
| トップ〜インパクト | 別の6制御点で区間全体を近似 | 保存点を間引き、局所的な曲線で結ぶ |
| インパクト〜フィニッシュ | さらに別の6制御点で区間全体を近似 | トップ以降の線として通常の描画を続ける |

今回確認したのは添付の静止画、現在の作業ツリーのコード、検証動画を生成したコード。端末内バイナリの版や実行ログは取得していないため、端末固有の別要因がないことまで証明する調査ではない。ただし、期待との差は上記の適用範囲だけで説明できる。

## コード上の根拠

1. **検証版**：`build/hand-fit/fit.py` の `stages` はアドレス〜トップ、トップ〜インパクト、インパクト〜フィニッシュの3つ。
   `fitted=[fit(p,n) for p in stages]` によって各区間に同じ制御点数の近似を実行している。
   `build/hand-fit/video/render.swift` は `Fit 6` の全区間を右側に描く。
2. **アプリの近似作成**：`SwingDuet/Models/HandTrailFit.swift` の `prepare` は、`time < phases.top` の点と
   接続用のトップ以降の最初の1点だけを近似へ渡す。ダウンスイング・フォローの近似は生成しない。
3. **アプリの描画**：`SwingDuet/Views/Stage/JointTrailOverlay.swift` では
   `fit: afterTop ? nil : fits[index]` として、トップ以降の線に近似を渡さない。
   `linePath` は近似がないと `played` → `curve` の通常描画に進む。
4. **計算の呼び出し元**：`VideoPaneView` のキャッシュもこの `HandTrailFit.prepare` を呼ぶ。
   キャッシュを作り直しても、適用範囲はバックスイングのまま。

## トップ以降に揺れが残る仕組み

通常描画は保存された多数の点から最大約80点を採り、その近くを通る一様3次Bスプラインでつなぐ。
点列に残っている蛇行や折り返しを、区間全体の運動として抑える処理は掛からない。
そのため曲線の接線が連続でも、見た目には細かな曲がりが残る。

また、通常描画は再生位置までの点列に現在位置を足して曲線を作り、末尾をその位置へ合わせる。
再生中の先端付近では形が変わり得る。区間全体の曲線を先に固定する検証版とは、この点も異なる。
ただし静止画から時間方向の揺れ自体は判定できない。

## 適用を限定した理由と検証の不足

[元動画での検証](260915_0328-hand-fit-video-check.md) では、フォロー〜フィニッシュの先端が手首から離れる場面があった。
そのため実装時に近似をバックスイングへ限定した。結果として、全区間近似した検証動画と同じ見た目にはなっていない。

実装後のPython版との数値一致確認もバックスイングの501時刻だけを対象にしており、全3区間が同じ方式で描かれることを確認したものではなかった。
単体テストも限定した実装の計算・接続を検証するため、検証動画と適用範囲が違うことは失敗として検出されない。

## 修正する場合の対象

サンプルの全区間の滑らかさを実現するには、近似の作成・保持・描画を3区間へ拡張する必要がある。
単に `afterTop` の条件を外すだけでは、バックスイング用の曲線を後半にも渡してしまうので正しくない。

- アドレス〜トップ、トップ〜インパクト、インパクト〜フィニッシュの近似を別々に保持する。
- 各区間の線と先端を、その区間の近似から求める。欠測による線の切れ目も保持する。
- トップ・インパクトの接続と、フィニッシュ付近の先端のずれを同じ元動画で確認する。
- 全区間について、検証版とアプリの描画を比較するテスト・比較動画を残す。

本調査ではアプリのコード・設定を変更していない。
