## 1. 保存データを失う 3 つの経路（最優先）

いずれも「静かに失われて、気付いたときには戻せない」種類のもの。

### 1.1 `library.json` を読めないと `Documents/Videos/` の動画を全部消す

起動時の並びが

```swift
if let library = readLibrary() { load(library) }   // 復号に失敗すると clips は空のまま
removeUnreferencedModels()
removeUnreferencedVideos()                          // 参照＝空集合として全ファイルを削除
```

だったため、**保存データが 1 度読めないだけで、参照されていない＝すべての動画ファイルが消えていた**。
消えるのは写真ライブラリに無いもの（OS ピッカー経由で取り込んだ動画・写真ライブラリへの保存に失敗したショット・
撮影して本番と決まる前の球）で、どれも戻せない。

読み込みの結果を「初回 / 読めた / 読めない」の 3 値にし、**読めないときは後片付けをせず、保存データを
`library-<日時>.bak` に退避する**ようにした。一部のクリップだけ読めなかったときも同じ扱いにする。

### 1.2 クリップ 1 本の綻びが全部を道連れにする

`Library` は `clips` を 1 つの配列として復号していたので、**1 本でも解けなければ全体が読めない**（→ 1.1）。
`Pairing` は合成デコーダのままで、フィールドを 1 つ足した次のビルドが既存の保存データを読めなくなる形だった。

- クリップは 1 本ずつ復号し、解けなかった分だけ落とす（`Library.hasUnreadableClips` を立てて後片付けを止める）
- `Pairing` に寛容な `init(from:)` を足し、相手の情報が読めなくてもクリップは残す（相手はいつものお手本に落ちる）

### 1.3 起動の途中でディスクに書き、`splitTakes` を空に上書きする

`load` の代入順が `clips → playback → capture → splitTakes` で、`playback` の `didSet` が
（まだ復元していない）`splitTakes` を**空のまま**書き出していた。保存された再生の設定が既定と違えば毎回起きる。
影響は「1 球ずつに分けて取り込み済み」の印が消えること＝同じ長い動画をもう一度選ぶと二重に分割される。
読み込みの間は `didSet` の保存を止めるようにした。

**あわせて**：`persist()` の `try?` が符号化の失敗（数値が NaN など）を握りつぶし、以後すべての保存が
静かに失敗し続ける形だった。失敗はログに残し、NaN の入口（壊れた動画の長さ）は解析の入口で弾くようにした。

## 2. 撮影：760 行に畳まれていた 10 の仕事を割る

`CaptureController` は帯（`shots`）と切り出しの列（`cuts`）という**同じものを 2 本の配列で持ち、6 か所で手で
同期**していた。片方だけ更新するのがいちばん起きやすい壊れ方で、しかも状態遷移のテストが 1 行も書けなかった。

- **`ShotPipeline`**（新）：1 球が帯に出てから片付くまでの状態機械。仕事の列を唯一の真実にし、帯はそこから作る。
  切り出しは `Exporting`、保存は `Storing` 越しなので、カメラも Vision も PhotoKit も無しでテストできる
- **`SegmentStore`**（新）：閉じた区切りファイルの置き場。「消してよいか」を録画の状態ではなく
  (a) まだ切り出していない球が参照しているか (b) 保持期間 (c) 全体の動画に要るか、で決める。
  **[TODO.md](../TODO.md) K の「止める途中で全体の動画に要るファイルを消す」が構造として起きなくなった**
- 状態の導出：`edge`（縁の色）は「構え・熱・＋1 の点滅」の 3 つの事実から、`statusText` は状態から導く。
  点滅の前の色を覚えて戻す復元コードと、熱が冷めたときの後始末が消えた
- `Phase` → `RecordingState`（スイングの 4 フェーズと紛らわしい）
- 背景で止めるときの持ち時間切れ（満了ハンドラ）と、空きが足りないときは全体の動画をつながず区切りのまま残す
- 帯は `LazyHStack`（1 セッション 100 球のサムネイルを撮影中に全部作らない）

## 3. そのほかの修正

- 同じ写真ライブラリの動画を「お手本に追加」するたびに重複が増えていた（役割を見ずに先頭一致していた）
- ジョグホイールを止めずに 64 周回すとギアが 0 になり、コマが進まなくなる（`1 << laps` の桁溢れ）
- 一覧のサムネイルが iCloud にしか無い動画の本体をダウンロードしうる経路を止めた（1 巡目からの続き）
- 純粋計算の層の不到達条件（`torso > 0` の二重確認、常に非 nil の Optional、`?? 1` の空配列分岐、
  構え判定の矩形の二重追加）と、命名（`gap` → `afterGap`、`reappear` → `followStart`、`riseSpeed` → `backswingPeakSpeed`）
- 保存データを整形しない（`.prettyPrinted` をやめて `.sortedKeys` だけに。軌跡込みで数 MB あり、
  人が読む形にする利得より、メインスレッドで符号化する重さの方が大きい）
