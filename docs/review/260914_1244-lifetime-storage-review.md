# 保存・撮影・再生の全体レビュー

## 対象と結論

`316ac2a` の変更だけでなく、Models・Services・Views とテスト、仕様・設計の整合性を確認した。
保存形式の版 2 と外部依存ゼロを維持し、データ保護と非同期処理の境界で見つかった不具合を修正した。
設計方針は [保存と非同期処理の寿命の整合性](../design/260914_1140-lifetime-and-storage-safety.md) を参照。

## 修正内容

| 問題 | 修正と主な対象 |
| --- | --- |
| 読み込みエラーを新規起動と扱う、未知の版・参照の復号失敗・重複 ID を正常扱いすることで動画整理が走る | `ClipStore` と `Library` の読み込み判定を厳格化。動画がある状態での JSON 不在も保護し、退避失敗時を含めホームに保存停止を常時表示 |
| 写真への移動中に削除したクリップを戻すと、削除済みファイルを参照する | 移動完了時に削除取り消し用の参照も更新。JSON 保存成功後に、他のクリップと取り消し用の参照を確認してファイルを削除 |
| 撮影の帯から項目を消すと、実行中の切り出し・写真保存が停止時の待機から外れる | `ShotPipeline` の表示項目と実行中タスクを分離。入力区切りを保護し、削除後の出力も片付け終えるまで待機 |
| 最後の区切りだけを待つため、先行する区切りの完了が撮影停止後に届く | `CaptureController` が全区切りの書き込みとメインへの通知を待ち、その後に検出結果・切り出しを確定 |
| 撮影終了処理と画面破棄が競合する、保存に失敗した原本を後片付けで消す | 終了処理が後片付けを所有。作業動画を `Documents/CaptureTakes/Pending-<UUID>/` に置き、全体動画の保存・退避失敗時に保持。結合処理をメインスレッド外へ移動 |
| 書き込みが失敗状態でも録画を続行する、容量不足時にログ書き込みが安全に終了しない | `SegmentWriter` の状態を確認して停止へ通知。`CaptureLog` をエラー捕捉できる書き込みに変更 |
| 動画の分割中に最後の書き出しが失敗すると元 ID が失われ、途中の編集も消える | 最後に成功したショットが元 ID を引き継ぎ、完了時点の名前・お気に入り・相手を反映 |
| 画面を閉じた後に動画の読み込み結果を反映する、同じ ID の保存先変更に追従しない | 動画の識別に ID と保存先を使い、読み込み完了時のキャンセルを確認。リプレイのプレイヤーとループを明示的に破棄 |
| プレビューの読み込み失敗が空画面になり、お手本の再解析案内が操作と合わない | 読み込み中・エラーを表示し準備前の決定を無効化。カードとステージに再試行の操作を用意 |
| 短い動画でフェーズやループの最低幅が動画長を超える | 動画長に応じて間隔を制限し、保存済みループ範囲も共通時間軸内へ正規化 |

## 検証結果

- iPhone 16e / iOS 26.2 シミュレータで `SwingDuetTests` が成功。167 テスト、パラメータ展開後 177 実行、失敗・スキップとも 0。
  保存保護・削除取り消しとの競合・分割 ID・非同期処理の待機・短い動画の境界を追加した。
- 短い動画のフェーズとループの回帰テストは修正前に失敗することも確認した。
- 最終の撮影退避失敗時の分岐修正を含め、署名なしの実機向けビルドが成功。
  単体テストの成功後に追加したこの分岐は、実機で容量不足を起こす試験までは実施していない。
- `316ac2a` と修正後をそれぞれ解析 CLI としてビルドし、手元の MP4 サンプル 4 本で比較。
  処理時間表示を除き、検出結果の出力は一致した。動画を外部へ送信していない。
- `git diff --check` が成功。保存・撮影・再生の仕様とテスト案内を同時更新した。

検証ログは gitignore 対象の `build/review-baseline.log`、`build/review-device.log`、
`build/review-boundary-before.log`、`build/review-detection-{original,current}.log`。
単体テストの結果は `build/Logs/Test/Test-SwingDuetTests-2026.09.14_12-18-40-+0900.xcresult`。

## 残る確認と制約

- 実機のカメラ、PhotoKit の保存・権限、背景移行、保存容量不足を組み合わせた確認と画面全体の E2E は未実施。
  シミュレータの単体テストや解析 CLI の結果で代替できない。
- Swift 5 モードでビルドは通るが、撮影キューの非 Sendable 型を渡す警告と AVFoundation の非推奨 API 警告が残る。
  並行性の型による保証は [TODO.md](../TODO.md) の T に整理している。
- 保護して残した作業動画をアプリから復旧する導線と保存期限は未整備（TODO Z）。保存容量を使い続ける。
- 全クリップ操作の JSON 保存はトランザクション化されていない。今回の起動時保護と移動・破棄の保護だけでは、
  あらゆる実行中の保存失敗に対する再起動後の復旧を保証できない。孤児動画の即時削除を退避へ変える課題と併せて扱う（TODO AB）。

Git の状態・履歴を変更する操作は行っていない。変更は編集済み・未コミット。
