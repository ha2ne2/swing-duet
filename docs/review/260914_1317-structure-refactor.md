# コード構成と編集範囲のリファクタ

コードベースを知らない人向けの説明は、[ずんだもんと四国めたんの SwingDuet 大改装見学](./260914_1410-refactor-dialogue-guide.md) を参照。

## 変更の要点

保存・撮影・比較画面を中心に、ファイルの役割と値の所有者を明確にした。
既存の動画保護・非同期処理の修正を維持し、保存形式の版 2 と画面の操作は変更していない。
方針は [構造整理の設計](../design/260914_1250-structure-refactor.md)、現行の配置は [アーキテクチャ §2](../ARCHITECTURE.md#2-モジュール構成) を参照。

| 対象 | 変更と理由 |
| --- | --- |
| `Services` | `Analysis`・`Library`・`Media`・`Playback`・`Capture` に整理。処理の入口を用途から探せるようにした |
| `ClipStore` | JSON と管理動画の操作を `LibraryFiles` へ分離。クリップの編集・参照の判断・解析キューに集中させた |
| 保存形式の移行 | `Library.migrated()` に集約。画面状態の復元と、保存データの版変換を分けた |
| `VideoConfig` / `Pairing` | 共通の位置合わせを `PaneTransform` にまとめた。JSON は従来の平坦なキーで読み書きする |
| 比較画面 | 動画設定全体の Binding を廃止。位置合わせだけを Binding で渡し、フェーズと倍率は保存時の操作として渡す。解析結果のコピーを再保存する経路をなくした |
| 左右の動画ペイン | 同じ View の組み立てを `VideoSide` の反復にまとめ、保存先だけを分岐させた |
| 撮影 | フレーム書き込みを `CaptureFrameWriter`、姿勢追跡を `CapturePoseProcessor` に分離。キューと停止時の待ち合わせは維持した |
| `ShotPipeline` | 表示項目を処理状態から導出し、切り出し開始フラグを廃止。実行中タスクと入力の保持に必要な時刻を1つの辞書で所有する |
| 型と補助ファイル | `Library`・`Pairing`・`VideoSource`・`SlowFactor`・`VideoSide`・`VideoError` を独立ファイルへ。解析結果の導出は `Analysis/SwingAnalysisResult.swift`、汎用拡張は `Support`、カメラプレビューは `Views/Capture` に配置 |
| コメント | 長い操作説明や過去の移行経緯を削り、責務・単位・所有権・失敗時の制約を先に示す形へ整理。数値の根拠やシーク・停止・保存の注意点は保持した |

Xcode のファイル自動収集を利用しているため、プロジェクト設定の手作業の追加は不要。
CLI のビルド指定と、現行のガイド・設計文書の実装パスを更新した。調査・レビューの過去時点の記録は保持している。
